# Module 33 — Acronym Cheatsheet

**Topic:** React Component Development  
**Use when:** reviewing slides, pre-lab exercises, or the module lab. Quick meanings in plain language; full forms match how this module’s deck uses each term.

_Derived from **22** curriculum slide diagram title(s) plus slide text for this module._

---

## Frontend

| Term | Full form | Simple meaning |
| --- | --- | --- |
| **DOM** | Document Object Model | Browser’s tree of HTML elements. |
| **HTML** | Hypertext Markup Language | The markup language JSX resembles; browsers render it directly. |
| **JSX** | JavaScript XML | Syntax that looks like HTML inside JavaScript/React. |
| **Node.js** | — | JavaScript runtime used for tooling and some backends. |
| **npm** | Node Package Manager | Installs and runs JavaScript packages. |
| **Props** | Properties | Inputs passed from parent to child React components. |
| **React** | — | Library for building UI from components. |
| **SPA** | Single-Page Application | Web app that updates in the browser without full page reloads. |
| **TSX** | TypeScript XML | `.tsx` file extension: a TypeScript file that also contains JSX (Lab 33 uses `.tsx` for components, plain `.ts` for non-component files). |

## Accessibility

| Term | Full form | Simple meaning |
| --- | --- | --- |
| **A11Y** | Accessibility (11 letters between "a" and "y") | Shorthand for designing UI usable by everyone, including screen-reader and keyboard-only users. |
| **ARIA** | Accessible Rich Internet Applications | Attributes like `aria-label` that give assistive technology extra context about an element. |
