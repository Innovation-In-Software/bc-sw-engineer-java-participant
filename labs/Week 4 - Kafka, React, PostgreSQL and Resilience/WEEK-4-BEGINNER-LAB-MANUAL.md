## PostgreSQL Dialect Note for Labs 37-39

Week 4 database labs are PostgreSQL labs. If an older guide or comment uses Oracle-style terms, use the PostgreSQL equivalent below:

| Older/Oracle-style wording | PostgreSQL equivalent for this manual |
| --- | --- |
| `NUMBER` for identifiers | `BIGINT` or `BIGINT GENERATED BY DEFAULT AS IDENTITY` |
| `DBMS_STATS` | `ANALYZE table_name;` |
| `DBMS_XPLAN` | `EXPLAIN (ANALYZE, BUFFERS)` |
| `TRUNC(created_at)` | `date_trunc(...)` for contrast, or a half-open timestamp range for optimized SQL |
| `DROP TABLE ... CASCADE CONSTRAINTS PURGE` | `DROP TABLE IF EXISTS table_name CASCADE;` |
| ORA error codes | PostgreSQL SQLSTATE codes such as `23505`, `23503`, and `23514` |

### Code or Configuration

The listener validates the Kafka key before calling the handler. This prevents a malformed event from causing the wrong customer side effect.

```java
@KafkaListener(topics = "${crm.kafka.customer-topic}", groupId = "crm-notifications")
void receive(CustomerEvent event, @Header(KafkaHeaders.RECEIVED_KEY) String key) {
  if (!key.equals(event.customerId())) {
    throw new InvalidCustomerEventException("Kafka key must match customerId");
  }
  if (!processedEventStore.markIfNew(event.eventId())) {
    log.info("duplicate_event_ignored id={}", event.eventId());
    return;
  }
  notificationHandler.handle(event);
}
```

```typescript
export async function request<T>(path: string, init: RequestInit = {}): Promise<T> {
  const response = await fetch(`${API_URL}${path}`, {
    ...init,
    headers: {
      "Content-Type": "application/json",
      "X-Correlation-Id": "lab-request-001",
      ...init.headers,
    },
  });
  if (!response.ok) throw await ApiError.from(response);
  if (response.status === 204) return undefined as T;
  return response.json() as Promise<T>;
}
```
